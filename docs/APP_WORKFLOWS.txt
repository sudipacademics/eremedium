0a) UNIFORM LAB MODEL (architecture of record)
----------------------------------------------
  Full text: docs/UNIFORM_LAB_WORKFLOW.md
  Diagram:   docs/blood-collection-to-report-workflow.png

  Target shape:
    Multiple booking inputs (www, Flutter, partners Bill Entry / B2B, collect assist)
         → HEC APIs on ERPNext mint Customer TRF.unique_barcode once
         → From that barcode through Lab Report PDF is one unique chain
         → health_web_app SPA = employee frontend (role dashboards)
         → ERPNext = data receiver / source of truth
         → ERP Desk = masters, admin, exceptions (not daily collect–test–authorize)

  Multi-input → single barcode:
    Patient web/app  → book_lab_test / create_customer_trf  → DocType barcode
    Partners B2B     → create_b2b_walk_in_order             → DocType barcode
    Bill Entry       → TRF insert (target: leave barcode blank; DocType only)
    Tubes            → accession_id = {unique_barcode}-{TUBE} (logistic overlay)
    LIS / analyzers  → get_barcode_tests / log_machine_result on unique_barcode

  Post-barcode ops (SPA roles):
    Phlebotomist  collect …/dashboard/phlebotomist     Sample Collected
    Reception     www accession (Phase 89 APIs)          receive / reject tubes
    Lab tech      www …/dashboard/lab-reports            grid + finalize Verified
    Pathologist   same report UI                         authorize PDF + notify
    Patient       www / Flutter /bookings                 download PDF

  Result-store contract: LIS writes Lab Test Result; humans edit Lab Report
  Parameter (after import); finalize syncs Report → LTR. No dual edits after Verified.

  Known gap until live deploy: SPA LabReports* routes are wired in App.tsx locally;
  Desk Lab Report remains available as exception path until parity is proven in production.

4) PATIENT WORKFLOW  —  www.e-remedium.in
==============================================================================

A. Register / login
   1. Open /signup or /login
   2. Email path: register_patient → verify email → login
      OR mobile OTP: send_otp → verify_otp_and_login (test OTP often 123456)
   Key methods: register_patient, authenticate_user, send_otp, verify_otp_and_login

B. Discover centres
   1. Open /centres
   2. UI calls public RFMS: GET /rfms-api/v1/public/centres
      (franchisees stage=onboarding_completed; Get Direction = saved Maps URL)

C. Book lab test (TRF → pay → results)
   1. /diagnostics → pick test → /diagnostics/book/:item
   2. book_lab_test / create_customer_trf
   3. create_razorpay_order → Razorpay Checkout → verify_razorpay_payment
   4. Track: /bookings, /bookings/:trfId → get_my_bookings + report/journey APIs
   5. Downstream: LIS / results pipeline (native ERPNext + lab roles)

D. Account
   /account — profile, bookings history

Pages (SPA): /, /diagnostics, /centres, /bookings, /account, /dashboard/staff (staff)

6) REACH SALES  —  reach.e-remedium.in/sales
==============================================================================

A. Login
   /login → /sales (Sales Representative or Sales Manager)

B. Lead management
   1. /sales/leads — list/create/filter (source, campaign, district/PIN Phase 84)
   2. create_sales_lead / get_sales_leads
   3. Assign to another REACH rep (manager): assign_reach_sales_lead

   1. /sales/visit — create Field Sales Visit (GPS, notes, photos)

   1. /sales/onboard — “Start e-Aadhaar / e-agreement”
   2. submit_sales_onboarding → create_onboarding_session (HMAC token)
   3. Browser opens:
        https://www.e-remedium.in/onboard/hec-session?token=…
   4. RFMS creates CRM lead only (source=reach_sales, blank FOFO/FOCO)
   5. Redirect /onboard?hec_lead=&hec_fp=… → applicant picks model (see §8)

E. Reports / map / franchisees
   /sales/reports — territorial rollup (district)
   /sales/map — team by district
   /sales/franchisees, /catalog, /commissions

Key methods: get_sales_leads, create_sales_lead, log_sales_visit, get_sales_visits,

8) APPLICANT ONBOARD (FOFO/FOCO)  —  www.e-remedium.in/onboard
==============================================================================

Sources of an applicant session:
  A) REACH Phase 80 mint → /onboard/hec-session?token=… (prefilled, model blank)
  B) Marketing /franchise → apply CTA → /onboard (organic)
  C) Direct /onboard

Fresh path (Phase 82a + 83 payments/OTP):
  1. Select FOFO or FOCO
  2. Create account (user_id + password) OR continue session
  3. Contact OTP (mobile/email) via ERP MSG91 when RFMS_CONTACT_OTP_VIA_ERP=1
     Dev fallback: RFMS_OTP_DEV_FALLBACK / otp_test_mode → 123456
  4. KYC documents + e-Aadhaar / agreement steps as enabled
  5. First payment:
       POST /rfms-api/v1/.../payments/gateway/initiate
       → ERP create_rfms_razorpay_order (HMAC) → Razorpay Checkout.js
       → gateway/complete → verify_rfms_razorpay_payment
       Simulate only if RFMS_GATEWAY_SIMULATE=1 or ERP test without key_id
  6. Only after payment: application visible_to_admin=true → /ffms Applicants
  7. Later completion: ingest_onboarding_result → Franchisee Profile (ERP)
  8. Paid milestone (Phase 85c): activate_rfms_paid_franchisee
       → hub profile + wallet OPENING-RECHARGE

RFMS public application routes (under /rfms-api/v1):
  POST /applications/public
  contact OTP, document upload, aadhaar okyc
  payments gateway initiate/complete, offline submit, receipt verify

Portal static: /onboard/*
Do NOT confuse with /franchise (marketing chrome) — portal header is applicant-only.

9) FFMS OFFICER ADMIN  —  www.e-remedium.in/ffms
==============================================================================

A. Login
   Company ID (RFMS-NNNN) or email + password
   POST /rfms-api/v1/auth/login  { login_id, password }
   OTP for officers is disabled (OTP_DISABLED)
   Session: GET /auth/me · logout POST /auth/logout

B. Modules (typical day)

   Overview
     KPIs + territory availability strip; maps key from
     GET /admin/integrations/maps-key (ERP HEC browser key preferred)

   User Management
     List/create officers → next ID RFMS-0008+
     GET|POST /admin/users · GET /admin/users/next-employee-id
     PATCH cannot change assigned company ID

   Applicants
     Review FOFO/FOCO apps after first payment
     GET /applications · progress stages · Video KYC / agreements queues as enabled

   Payments
     Ledger, receipt download/verify, coupons
     Paid FOFO fee / FOCO deposit triggers hub activation (85c) — fail-soft if ERP down
     Receipt PDF vs QR JSON: admin receipt route vs /receipts/verify/RCP-…

   Territory Setup + Capacity (85b)
     Google map: Active / Available / Reserved / Occupied (WB geo Phase 84)
     GET /geo/wb-hierarchy · GET /geo/pincode/:pin
     GET /territories · POST territories · availability / pincodes
     Capacity ops: GET /territories/capacities (?format=csv)
                   GET /territories/capacity-alerts?threshold=1
                   PATCH /territories/capacities/bulk

   Lead Management (+ ads + WhatsApp)
     List/filter Meta/Google/WhatsApp/organic
     Assign CRM / BC / Reach; stage actions sync to REACH when configured
     GET|POST /leads · GET /leads/:id · POST /leads/:id/actions
     CSV: POST /leads/import
     Ads status: GET /leads/ads/status
     WhatsApp thread: GET|POST /leads/:id/whatsapp
     Inbox filter: WhatsApp inbox

   Log Visit
     Field visits from REACH + officer-created
     GET /sales-visits
     GET /sales-visits/reach-reps
     POST /sales-visits/assign-lead  (push to REACH Field Sales Visit)
     Performance panel; visit GPS/photos when present

   Other
     Appointments, Training, Franchisee Directory, Content CMS, Support
     Partner reads: GET /partner/franchisees

C. Integration config (Phase 83)
   Public: GET /integrations/public-config (Razorpay key_id flags — no secrets)
   Secrets stay on ERP Health Ecosystem Settings

12) CROSS-SYSTEM CLOSED LOOPS
==============================================================================

12.1 Phase 80 — REACH → Onboard → FFMS → ERP profile

    → create_onboarding_session (HMAC)
    → GET /onboard/hec-session?token=
    → RFMS CRM lead (reach_sales, blank model)
    → Applicant FOFO|FOCO + KYC + pay
    → Officer Applicants
    → ingest_onboarding_result / activate_rfms_paid_franchisee
    → Franchisee Profile + Partners wallet

12.2 Phase 86 — Ads → ERP + RFMS + REACH
  Meta Lead Ads / Google Lead Forms
    → POST www /api/method/...ingest_franchise_ad_lead
       (hub.verify + X-Franchise-Ads-Secret)
    → Upsert Franchise Sales Lead (REACH)
    → POST RFMS /leads/ingest/ad
  Fallback: CSV import in FFMS; thin /leads/webhooks/meta|google

12.3 Phase 87 — WhatsApp Cloud ↔ FFMS inbox
  Meta Cloud webhook
    → ingest_whatsapp_cloud_webhook
    → HEC WhatsApp Conversation / Message
    → RFMS /leads/whatsapp/link | /inbound
    → FFMS Lead CRM thread + reply (GET|POST /leads/:id/whatsapp)
  Outbound notifications: Meta preferred; Gupshup fallback (whatsapp_provider)

12.4 Bidirectional leads & visits (REACH ↔ FFMS)
  REACH create/update lead / visit → RFMS ingest
  FFMS assign REACH rep / status → ERP ffms_assign_reach_lead / ffms_update_lead_status
    → Field Sales Visit Assigned on REACH; complete with photos syncs back
  Internal ERP→RFMS base URL MUST be http://rfms:8090/api/v1 (not public www from Docker)

12.5 Phase 84 — WB geo SoR
  ERP HEC WB Postal Locality (~341 rows)
    → RFMS geo hierarchy / pincode resolve
    → Territory picklists + map; REACH district/PIN on leads & reports

12.6 Phase 85 — Territory capacity + paid hub activation
  Officers bulk-edit FOFO/FOCO capacity; CSV export; near-full alerts
  Paid FOFO one-time fee OR FOCO deposit/full → activate_rfms_paid_franchisee
  Disable hub activate: RFMS_HUB_ACTIVATE_ON_PAY=0
